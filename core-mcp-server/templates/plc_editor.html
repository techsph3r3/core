IEC 61131-3 Structured Text

Structured Text (ST) is a high-level programming language for PLCs, similar to Pascal. It's one of five languages defined by IEC 61131-3 standard.

// Basic ST syntax
IF sensor_active THEN
conveyor_run := TRUE;
END_IF;

Key Concepts

Variables (%I, %Q, %M)

%IX = Input bits, %QX = Output bits, %MW = Memory words

Scan Cycle

PLC executes program repeatedly (e.g., every 10ms)

Edge Detection

Detecting signal transitions (rising/falling edge)

Timers & Counters

Built-in timing functions (TON, TOF, CTU, CTD)

Critical ICS Security Risks

Modifying PLC logic can have serious real-world consequences. Always consider these risks:

Safety System Bypass

Disabling or modifying emergency stop logic, interlocks, or alarm systems can lead to:

  • Equipment damage
  • Personnel injury
  • Environmental incidents
Example: alarm := FALSE silences warnings during actual faults

Force Mode Abuse

The force registers allow external override of PLC outputs. Malicious use can:

  • Start equipment unexpectedly
  • Override safety interlocks
  • Cause process disruption

Timing Manipulation

Incorrect timing parameters can cause:

  • Packages not sorted correctly
  • Equipment collisions
  • Production failures
Example: Setting calc_delay := 0 activates diverters immediately

Logic Errors

Common programming mistakes:

  • Division by zero (speed = 0)
  • Integer overflow in counters
  • Missing edge detection causing repeated triggers
  • Race conditions between timers

Best Practices

  • Always test in simulation before deploying to real PLCs
  • Never disable safety systems
  • Use edge detection for buttons/sensors
  • Add bounds checking for calculated values
  • Document all changes with comments
  • Keep backup of working code
